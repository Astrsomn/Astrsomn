# Astrsomn 存储与多模态处理设计文档 (V1.0)

## 1. 设计背景
在制造业（CRM/MES/WMS） AI 化进程中，文件（特别是图片与文档）的流转是核心痛点。本设计旨在通过一套标准的存储抽象层，解决业务系统集成 AI 时面临的存储多样性、网络连通性及多模态数据转换问题。

## 2. 核心设计原则
*   **职责分离**：业务系统负责“对话图片”的上传；框架 Server 负责“知识库文件”的管理。
*   **存储抽象**：屏蔽云厂商 SDK 差异，统一使用 S3 协议或成熟中间件（X-File-Storage）。
*   **网络中立**：支持公网链接透传与内网 Base64 转换，适配工业私有化部署。

---

## 3. 模块架构
项目将新增/优化以下模块：

| 模块名 | 职责描述 |
| :--- | :--- |
| `astrsomn-storage` | **存储适配层**。基于 `X-File-Storage` 封装，支持本地、S3、阿里云、华为云等。 |
| `astrsomn-core` | **协议处理层**。定义 `FileConverter`，将业务 URL 或 Base64 转换为 LangChain4j 的 `Content`。 |
| `astrsomn-ui` | **无状态组件层**。Vue 聊天组件提供上传 Hook，解耦业务上传逻辑。 |
| `astrsomn-server` | **管理控制台**。利用 storage 模块进行知识库文件的持久化存储与管理。 |

## 4. 详细流程设计

### 4.1 多模态对话图片流转 (无感集成)
1.  **前端上传**：用户在 `AstrsomnChat` 组件选择图片，组件触发 `on-upload` Hook。
2.  **业务存储**：业务方将图片存入其自有系统，返回 `fileId` 和 `previewUrl`。
3.  **协议提交**：组件将 `previewUrl` 封装在 Chat 消息中发送至后端。
4.  **模型适配**：
    *   **公网模式**：Core 直接将 URL 包装给 LangChain4j。
    *   **私有/内网模式**：Core 识别到内网 URL，通过适配器将其转为 Base64 后喂给模型。

### 4.2 知识库文件流转 (托管模式)
1.  **配置**：用户在 Server 控制台配置 OSS 密钥（存储于 `astrsomn-storage` 配置项）。
2.  **上传**：Server 直接调用存储模块将 PDF/Doc 写入 OSS。
3.  **关联**：在数据库记录 `file_id`、`original_name` 及 `oss_key`，并在 Bento Grid 界面展示。

## 5. 关键接口与数据结构

### 5.1 后端存储接口 (astrsomn-storage)
```java
public interface AstrsomnStorageClient {
    /** 上传文件 */
    StorageResponse upload(InputStream inputStream, String fileName);
    /** 获取文件访问/下载地址 */
    String getFileUrl(String fileKey);
}
```

### 5.2 多模态消息协议 (astrsomn-core)
```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "分析这张异常图片" },
    { 
      "type": "image", 
      "source": {
        "type": "url", 
        "data": "http://mes-internal/data/img_001.png"
      }
    }
  ]
}
```

## 6. 前端组件封装策略 (`astrsomn-ui`)

### 6.1 AstrsomnChat 组件属性
| 属性名 | 说明 | 默认值 |
| :--- | :--- | :--- |
| `upload-url` | 简单的上传接口地址 | `/api/astrsomn/upload` |
| `custom-upload` | 函数钩子，用于业务方深度定制上传逻辑 | `null` |
| `image-resolve` | 图片预览地址解析函数（处理内网转公网或签名） | `(url) => url` |

## 7. 实施计划 (Roadmap)
1.  **阶段一 (Storage)**：在 `astrsomn-storage` 引入 `X-File-Storage`，实现 Local 和 S3 驱动。
2.  **阶段二 (Core)**：封装 `ImageContentHelper`，支持从 URL 自动检测并构建多模态消息。
3.  **阶段三 (UI)**：重构 Vue 对话组件，暴露出上传 Hook 接口。
4.  **阶段四 (Server)**：在控制台增加“存储配置”页面，打通向量库文件上传。
