# Astrsomn 扩展注册与卸载常见问题整理

本文整理你连续提到的几个核心问题，聚焦两条能力来源：
- `Maven/classpath` 依赖
- `plugins` 目录下的 `jar` 插件

---

## 1. Maven 与 SPI 插件分别在哪里注册？

分两层看：**元数据注册** 与 **运行时能力注册**。

### 1.1 元数据注册（扩展记录）
- 入口：`astrsomn-server/src/main/java/org/astrsomn/server/plugin/registry/SystemExtensionRegistry.java`
- 关键方法：`registerExtensions()` + `mergeDescriptors(...)`
- 行为：合并 Spring Bean 和 SPI 的 `AstroExtensionDescriptor`，写入/更新 `system_extension` 表。

### 1.2 运行时能力注册（真正可调用）
- Vector：
  - `classpath` SPI：`astrsomn-spring-boot-starter/src/main/java/org/astrsomn/starter/langchain/vector/AstroVecSourceFactory.java`
  - 启动构造时 `loadClasspathDrivers()` 通过 `ServiceLoader<VecDriver>` 注册驱动
- Jar 插件：
  - `astrsomn-spring-boot-starter/src/main/java/org/astrsomn/starter/plugin/AstrsomnPluginManager.java`
  - `loadPlugin()` 里加载 SPI 后，调用：
    - model：`astroModelFactory.registerHandler(...)`
    - vector：`astroVecSourceFactory.applyPluginDrivers(...)`

## 2. 引入 starter + vector 依赖后，用户能直接用吗？要自己写注册器吗？

结论：**通常不需要写自己的注册器**。

满足以下条件即可直接使用：
- 已引入 starter 和对应 `astrsomn-vector-*` 依赖；
- 该依赖内已提供标准 SPI 实现（`VecDriver`）；
- 数据库有可用的 `AiVecSourceEntity` 配置（provider/连接参数）；
- 状态为 `enabled` 且 `envCode` 匹配当前运行环境。

系统会自动：
- 通过 SPI 加载驱动；
- 在预热流程中建立/刷新运行时向量连接句柄。

只有在你要做“非标准 SPI 注册路径”或“特殊自动装配策略”时，才需要自己写额外注册逻辑。

---

## 3. classpath 是 Spring 的，SPI 是 JDK 的，对吗？

对，二者不同层次：

- `classpath`：类加载可见范围，不是 Spring 专属。
- `Spring Bean` 发现：基于注解/配置扫描，进入 IOC。
- `JDK SPI` 发现：`ServiceLoader + META-INF/services`，不依赖 Spring 容器。

你当前项目是**并行使用**两套机制：
- `SystemExtensionRegistry.mergeDescriptors(...)`：Spring Bean + SPI 合并；
- `AstroVecSourceFactory` / `AstroModelFactory`：直接用 SPI 加载运行时实现。

---

## 4. 为什么 Vec 有 ConcurrentHashMap 管理，Model 在哪里？

Model 也有 `ConcurrentHashMap`，但缓存维度不同。

### 4.1 Vec（重资源缓存）
- 位置：`AstroVecSourceFactory`
- 关键缓存：
  - `activeSources`：`sourceId -> VecSource`
  - `activeSourceFingerprints`：配置指纹
- 目的：管理每个数据源连接句柄的创建、复用、刷新、关闭、失效降级。

### 4.2 Model（路由缓存）
- 位置：`astrsomn-spring-boot-starter/src/main/java/org/astrsomn/starter/langchain/factory/AstroModelFactory.java`
- 关键缓存：
  - `handlerMap`：`providerCode -> ModelProviderHandler`
- 目的：按 provider 路由到处理器；模型客户端通常在请求时创建，不按 sourceId 长持连接。

一句话：**Vec 管连接生命周期，Model 管能力路由。**

## 5. 当同时有 jar 插件和 Maven 依赖时，怎么处理？

### 5.1 Vector：插件优先，依赖兜底
- 位置：`AstroVecSourceFactory.resolveDriver(...)`
- 规则：
  1. 先查 `pluginDriverOverrides`
  2. 查不到再回退 `classpathDrivers`
- 卸载插件后：`removePluginDrivers(jarName)`，能力回退到 classpath 驱动（若存在）。

### 5.2 Model：后注册覆盖先注册
- 位置：`AstroModelFactory.handlerMap`
- 启动先装 classpath handler，插件应用后 `registerHandler(...)` 会 `put` 覆盖同 provider。

## 6. 注册与卸载流程总览（依赖 + jar 两种）

## 6.1 Maven/classpath

### 注册（启动时）
1. `SystemExtensionRegistry.registerExtensions()` 同步扩展元数据；
2. `AstroModelFactory` / `AstroVecSourceFactory` 通过 SPI 加载运行时能力；
3. `EnabledVecSourceWarmup` 对启用向量源做启动预热。

### 卸载
- classpath 依赖通常不做“在线卸载”；
- 一般是移除构建依赖后重启生效。

## 6.2 Jar 插件

### 注册/应用
1. 元数据解析：`ExtensionJarMetadataReader`（独立 ClassLoader + SPI）；
2. 生命周期编排：`SystemExtensionLifecycleOrchestrator.apply(...)`；
3. 策略执行：`ModelExtensionStrategy` / `VectorExtensionStrategy` / `McpExtensionStrategy`；
4. `AstrsomnPluginManager.applyPlugin(...)` 加载 jar 内 SPI；
5. 能力检查通过后，扩展状态更新为已应用。

### 撤销/卸载
1. `revoke(...)`：先 guard 校验引用，再 `pluginManager.unloadPlugin(...)`，状态回 `INSTALLED`；
2. `uninstall(...)`：策略卸载后删扩展记录，并尝试删除插件 jar 文件。

---

## 7. Vector 的额外重点：预热与失败降级

- 应用后增量预热：`VectorProviderWarmupService.warmupEnabledSourcesForProvider(...)`
- 启动后全量预热：`EnabledVecSourceWarmup.run(...)`
- 连接测试失败：移除缓存并把向量源状态写回 `DISABLED`。

这也是 vector 与 model 在“运行时管理复杂度”上的最大区别。
