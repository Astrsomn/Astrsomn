# Astrsomn Workflow 实例层：分阶段落地路线图

## 1. 路线总览
- 目标：以最短路径形成 Dify 风格的“可发布 + 可运行 + 可追踪”能力闭环。

## 2. 里程碑规划

### M1：发布与测试闭环（V1 必做）
- 交付：
  - `publish` 接口落地
  - DSL 编译器与校验器
  - 同步 `test-run` 执行通路
- 验收：
  - 前端可发布并测试运行全节点流程
  - 有基础节点轨迹返回

### M2：生产实例异步执行（V1 必做）
- 交付：
  - `start-instance`、`detail`、`cancel`、`resume`
  - Worker 执行主链路
  - 实例状态机 + 节点历史落库
- 验收：
  - 支持失败重试与重启恢复
  - 人工节点可挂起与恢复

### M3：可观测与治理（V1 必做）
- 交付：
  - Trace/日志/指标统一规范
  - 限流、超时、幂等控制
  - 失败归因与告警
- 验收：
  - 可按实例定位问题到节点级
  - 具备 P95 运行时可视化

### M4：增强能力（V1.5 可选）
- 交付：
  - 编排策略增强（优先级队列、延时重试、灰度）
  - 事件总线与外部回调
- 验收：
  - 支持高峰稳定性与更精细治理

### M5：高级编排（V2 增强）
- 交付：
  - 子流程、补偿事务、运行回放
  - 跨集群容灾与多 Region
- 验收：
  - 复杂场景与企业级可靠性达标

## 3. 主要风险与应对
- DSL 演进风险：引入 schemaVersion + 兼容层。
- 并行一致性风险：实例分区队列 + 幂等键。
- 外部依赖波动：熔断 + 降级 + 可重放。
- 成本风险：按节点统计 token/tool 成本并做配额治理。

## 4. 回滚策略
- 发布版本回滚：切换 deployment latest 到上一个稳定版本。
- 运行回滚：暂停新实例，保留进行中实例完成。
- 灰度回滚：关闭灰度流量，回切稳定版本。
