# Astrsomn Workflow 实例层：可观测性与运维治理

## 1. 目标
- 让实例运行“可看见、可定位、可恢复”。

## 2. 日志规范
- 统一携带：`traceId/envCode/instanceId/nodeId`。
- 分层日志：
  - API 层：请求与响应摘要
  - 引擎层：状态迁移、调度决策
  - 节点层：输入输出摘要、耗时、重试
- 敏感字段脱敏（token、密钥、用户隐私）。

## 3. 指标规范
- 实例指标：启动量、成功率、失败率、平均时长、P95/P99。
- 节点指标：节点执行次数、失败率、重试次数、耗时分布。
- 资源指标：队列堆积、worker 并发、DB 写入耗时。

## 4. Trace 规范
- 每个实例一个根 trace。
- 每个节点一个 span，重试产生子 span。
- 人工节点挂起与恢复要串联同一 trace。

## 5. 治理策略
- 超时：实例级/节点级超时分层配置。
- 限流：按 `workflowKey` 与租户维度限流。
- 配额：调用 LLM/工具配额对齐 starter 侧策略。
- 熔断：外部依赖失败率过高时临时熔断。

## 6. 故障处理
- 自动重试：指数退避 + 最大重试次数。
- 死信处理：超过重试阈值进入 DLQ，支持人工重放。
- 灰度发布：新 deployment 先小流量验证。

## 7. 运维面板建议
- 运行总览：实例状态分布与趋势。
- 失败分析：按节点/错误码聚合。
- 人工任务：待办量、逾期量、平均处理时长。
